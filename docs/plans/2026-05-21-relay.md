# Relay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use top-level checkbox (`- [ ]`) syntax for runner tracking. Each checkbox is one future Relay slice and one intended commit boundary.

**Goal:** Build `relay`, a Bun + TypeScript CLI that executes runner-optimized implementation plans slice-by-slice through fresh `codex exec` sessions, verifies each slice, commits completed work, attempts one repair pass, and opens or updates a pull request.

**Architecture:** Relay is a dependency-free headless orchestrator with a thin executable at `tools/relay/bin/relay.ts` and focused modules under `tools/relay/src/`. The runner persists all state inside each isolated worktree under `.relay/`, treats the plan file as the source of task truth, and owns git, verification, repair, notifications, push, and PR creation. Codex sessions receive only one bounded task at a time and must not commit, push, or open PRs.

**Tech Stack:** Bun, TypeScript executed directly with `#!/usr/bin/env bun`, Bun test runner, Node/Bun standard APIs only, Git CLI, Codex CLI, GitHub CLI, macOS `osascript` notifications.

## Common Blocker Conditions

Every slice must stop and record a blocker note in this plan if it encounters one of these conditions:

- A command needs credentials that are unavailable, including `codex`, `gh`, or macOS notification permissions.
- A task would overwrite unrelated working-tree changes.
- A production deployment, destructive database operation, or secret-handling decision is required.
- The source checkout or Relay worktree is in merge, rebase, cherry-pick, bisect, or branch-mismatch state.
- Bun is unavailable and cannot be installed through the existing dotfiles bootstrap path.
- The current task proves too large for one fresh Codex session; split that checkbox into smaller top-level checkboxes under the same phase, complete only the first safe slice, and stop.
